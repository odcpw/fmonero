# fmonero 0.2 wallet workflow qualification

This qualification is scoped to the wallet/desktop features requested on 2026-10-13, with Monero 0.18.5.3 as the native oracle. It is not full Monero GUI parity or funded-payment/physical-device certification. The corrected 0.2.0 binary is installed at `~/.local/bin/fmonero`. Source, native, terminal and installer gates pass. Final live desktop launch/widget verification is pending because Omarchy refuses shell restart while the session is locked. See [.beads/evidence/software-qualified.json](../.beads/evidence/software-qualified.json).

## Evidence obtained

- Central workspace tests: 204 binary, 283 core and 3 protocol-mock tests passed (490 total); strict clippy, formatting and structural gates pass. They cover protected input, actual UI hit regions at multiple sizes, exact integer amounts, URI/checksum round trips, identity/row binding, transport policy, partial/uncertain payments and injected pending-ledger directory failures.
- Actual offline Monero: 17 checks passed, including seed restore preserving identity/open state, labeled subaddresses, account/contact mutations, exact payment requests, message signing/verification/tamper rejection, encrypted recovery with an independent password reopen, view-only creation, empty output/key-image exchange and old-password refusal/new-password reopening. These offline checks are included in the current [native-regtest-qualified.json](../.beads/evidence/native-regtest-qualified.json) and `tests/native-wallet.py`.
- Actual CLI integration: 4 guarded legacy-branch tests and 11 uninstall tests passed. These check pending/corrupt records, retained lock inodes, mutation exclusion, failure propagation, configured data-path protection and bounded/sanitized regular-file logs.
- Widget: 86 static checks, JS presentation checks, and actual windowless Quickshell shared-policy tests passed. Repeated atomic privacy/notification changes update while the app remains closed. Private error/progress content stays masked.
- Full end-to-end CLI: 906 passed, zero failed. Three explicit exemptions cover installed-Monero absence, interactive TUI JSON and plain-text robot docs; the last two have separate gates.
- Isolated valueless regtest: 23 native checks pass, including ordinary send/fee refusal/confirmation, proof creation/checking/scope tamper rejection, spent/full rescanning, view-only key images, unsigned preparation/description, decline, offline signing, actual signed submission, fault-injected pending-wallet inspection with the payment guard retained, and native incoming-event baseline/batch deduplication across CLI restarts after a simulated failed desktop acknowledgement. The alert helper deliberately delivers no OS notification. See [native-regtest-qualified.json](../.beads/evidence/native-regtest-qualified.json).
- Actual native transport: 18 checks pass, including loopback proxy startup with TLS disabled plus strong CA material, HTTPS/pin configuration and running-proxy mismatch refusal. See [native-transport-qualified.json](../.beads/evidence/native-transport-qualified.json).
- Actual TLS: the untrusted certificate is refused with zero added HTTP/plaintext; explicit trust carries HTTP over TLS. The minimal gateway is explicitly not blockchain qualification. See [native-tls-qualified.json](../.beads/evidence/native-tls-qualified.json).
- Actual terminal: 207 checks pass at 40×10, 80×24 and 120×40, covering mouse/keyboard controls, input ownership, masked secrets, exact review/typed confirmation, cancellation, privacy and clean exit. SGR injection tests the real app parser/hit regions; desktop mouse delivery is separate.
- Installation: exact tested binary hash matches the installed binary; repeated setup returns seven unchanged actions. The running shell still has its old QML until an unlocked normal restart. No lock bypass or owner-wallet operation was used.

Every native test uses temporary wallets, credentials and directories, loopback-only processes, all seven isolation variables, private files and owned-process cleanup. Fake-chain tests use upstream's test-only `--allow-mismatched-daemon-version`; that policy is never added to the production adapters. No owner wallet or valued/public-network payment is used. Private native inputs travel through sealed memfds and an echo-disabled PTY for mid-command unlock prompts.

## Findings and corrections

Review and real oracle runs found: stale menu/window identity; protected clients lacking connected-peer ownership proof; plaintext/proxy policy drift; unguarded legacy mutators; unmasked widget action errors; growing secret-input buffers; unsupported native CLI flags; password prompts requiring terminal stdin; saved Monero denominations affecting printed amounts; best-effort payment-ledger directory sync; pending wallets needing an inspection-only reopen; account-0-only reconciliation; omitted empty key-image arrays/unsigned weights; generic RPC error code -1 being misclassified; formatted native transaction receipts; empty/whitespace ledgers bypassing the interlock; and cancelled wallet prerequisites rearming on later polls. All confirmed findings are corrected with boundary regressions.

Corrections are exercised at their actual boundary: established socket ownership before private HTTP bytes, private input/PTY behavior, typed wire parsing, fault-injected durable state, actual CLI/Qt/native adapters and terminal interaction. A mock success alone does not qualify native cryptography or broadcasting.

## Performance and resources

One repository target directory, an advisory build lock and two build jobs limit concurrent build growth. Development/test output omits debug symbols and incremental caches. Warm CLI measurements use isolated identical commands, exact semantic checks and binary hashes; RSS includes process-spawn overhead and is not an allocation profile. The installed-binary measurements are in [perf-installed.json](../.beads/evidence/perf-installed.json); warm medians were about 3.0–6.5 ms and sample p95 up to 8.3 ms in the final recorded run. Other warm windows measured lower values, so no causal speedup or production latency guarantee is claimed. Large held UI payloads use boxes to avoid copying oversized enum variants; fixed secret-input buffers eliminate growth and unwiped freed prefixes. Artifact cleanup is recorded in the software report. No unmeasured speedup is claimed.

## Remaining acceptance boundaries

Physical Ledger/Trezor creation/opening/signing requires a connected device. Public-network payments with valued funds, large real-wallet scan/chain workloads and full production daemon lifecycle/doctor scenarios remain unqualified. Valueless fake-chain transaction interoperability establishes software behavior only. Recovery artifacts recover deterministic funds by rescanning; they exclude contacts, labels, notes and local history metadata. Incoming notifications claim candidates at most once, so delivery failure can miss an alert without automatic replay.

This is the add-feature, boundary-focused use of the gauntlet methods: pinned oracle comparisons, exact/round-trip contracts, fault/negative cases, full command inventory, measurements and two-agent review/fix passes. It does not claim the full multi-round mature-port certification bundle or full Monero GUI parity.

Multisig, mining controls, account tags and output freeze/thaw are outside this round. Implemented workflows and explicit limits are documented in [README.md](../README.md); the dependency queue remains in `.beads/`.
