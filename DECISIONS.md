- 2026-09-16 · orchestrator · Project created from `docs/FEASIBILITY.md`. Architecture: Rust CLI + `fmonero-core` + FrankenTUI (`ftui` 0.7) + Quickshell bar widget, in the fproton/fbittorrent house pattern. Node via JSON-RPC to a local unrestricted `monerod` (127.0.0.1:18081). Wallet via `monero-wallet-rpc` run as a systemd user unit (Monero's own engine; rides the FCMP++/Carrot fork for free), not wallet2 FFI and not the pure-Rust `monero-wallet` crate (no FCMP++, we would own persistence/reorgs). HTTP via `ureq` 3.4 + std threads + ftui `Subscription`; caches as postcard snapshots. No asupersync (nightly by default, no Digest auth, ftui's loop is blocking), no fsqlite (nightly-only on x86_64; fproton rejected it 2026-09-14), no tokio.

- 2026-09-16 · design · DESIGN.md v1 written. Wallet-rpc auth is Option 2 (MD5 Digest, `md-5 0.10`, ~110 lines in `rpc/digest.rs`) because loopback binding does not stop a web page POSTing `sweep_all` to 127.0.0.1 and a fee-less `--disable-rpc-login` would trade money safety for 110 lines; the credential is **not** generated by us — the wallet unit passes neither `--disable-rpc-login` nor `--rpc-login`, so `monero-wallet-rpc` writes its own 128-bit `monero-wallet-rpc.<port>.login` at mode 0400 into `WorkingDirectory=%S/fmonero/run` and deletes it on exit (`wallet_rpc_server.cpp:351-380`, `util.cpp:215-224,263`); `monerod` has no such generator (`core_rpc_server.cpp:349-350`) so it gets `rpc-login=fmonero:<32 hex>` inside `~/.config/fmonero/monerod.conf` at 0600 via `--config-file`, never in argv. Wallet-rpc port fixed at **18083** (18082 is monerod's ZMQ port) so unit, doctor, panel and robot-docs agree without discovery. The mock is a **Rust workspace member `crates/fmonero-mock`** (`publish = false`, never installed), not `mock_rpc.py`, because the Digest challenge and the request log are the thing under test and must not exist twice in two languages. `ureq` is pinned `default-features = false, features = ["json"]` so the binary contains no TLS at all, making "loopback plaintext only" a compile-time property; a remote node therefore reaches Monero only through `wallet set-daemon`, which `monero-wallet-rpc` executes itself. Address validation is **structural only** in core (length, prefix, base58 alphabet) with `validate_address` as the authority before every build, so no keccak crate enters the tree; `address::PREFIXES` plus `tests/fixtures/address-forms.json` are the single place a new FCMP++/Carrot form is added, and a test asserts the two stay the same length. Crash safety: `state.pending_send` records only `{txid, amount, fee, dest, relayed}` before `relay_tx` and never the tx metadata (it carries the tx secret key); while it exists every `send`/`sweep` exits 3. Without `--yes` the `do_not_relay` build is discarded rather than cached, since `do_not_relay` commits nothing and the TUI can hold the metadata in memory; the TUI's confirm modal requires typing the word "send". Exit codes 9-16 are `wallet_locked · node_syncing · doctor · doctor_partial · doctor_refused · insufficient_funds · invalid_address · tx_rejected`, and 10 is returned by `send`/`sweep` alone. Units are `fmonero-monerod.service` and `fmonero-wallet-rpc.service`, written disabled and started on demand; Arch's system `monerod.service` is detected and used read-only, with `node up` exiting 3 rather than starting a second writer on one LMDB. No ZMQ; `status` is five hot RPC calls plus a 60 s-cached cold set (which also makes the net-rate samples meaningful). `ftui-extras` takes `canvas` + `charts` only, `qrcode` takes `default-features = false`; TUI budget 1 800 lines over four screens. The pruned-chain disk floor is 120 GB and is marked AMBER in DESIGN §1.3 and in the doctor's own detail text, because it is an estimate and nothing on this machine has measured it.
